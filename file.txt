● Spendly is a personal expense tracker built with Flask. Its pitch is "Know
  where your money goes", and the amounts are shown in rupees (₹). It's
  currently a scaffold: the front end exists, but the actual tracking features
  don't.

  What exists
  - A Flask app (app.py) that serves three working pages: a landing page (/), a
    register page and a login page. It runs on port 5001 in debug mode.
  - Templates (base.html, landing.html, login.html, register.html), plus
    static/css/style.css and static/js/main.js.
  - The landing page advertises three features: logging expenses (category,
    amount, date, description), category and monthly breakdowns, and filtering
    by date range.

  What's still a stub
  - database/db.py contains only comments. It's meant to hold get_db(),
    init_db() and seed_db() for a SQLite database.
  - /logout, /profile, /expenses/add, /expenses/<id>/edit and
    /expenses/<id>/delete return placeholder text such as "coming in Step 7".
  - The register and login pages only render a template. Nothing handles form
    submissions, passwords or sessions.

  The placeholder text says "students will implement these", so this looks like
  a step-by-step course project. The order is database setup (Step 1), then
  auth, profile, and add, edit and delete expenses (Steps 3 to 9).

  The natural next step is Step 1, the SQLite setup in database/db.py. I can
  start on that if you like.

❯ explain the project structure to me                                           

● Here's how the project is laid out. It's a standard small Flask app:

  expense-tracker/
  ├── app.py                  # Entry point: creates the Flask app and defines 
  all routes
  ├── requirements.txt        # Python dependencies (Flask, Werkzeug, pytest, 
  pytest-flask)
  ├── .gitignore
  ├── database/
  │   ├── __init__.py         # Makes database/ an importable package
  │   └── db.py               # SQLite helpers (still a stub)
  ├── templates/              # Jinja2 HTML templates, rendered by Flask
  │   ├── base.html           # Shared layout: <head>, navbar, footer, CSS/JS 
  links
  │   ├── landing.html        # Home page (hero, feature cards, call to action)
  │   ├── login.html          # Sign-in form
  │   └── register.html       # Sign-up form
  └── static/                 # Files served as-is at /static/...
      ├── css/style.css       # All site styling
      └── js/main.js          # Client-side JS (currently empty)

  How the pieces connect

  1. app.py is the hub. Each @app.route maps a URL to a function. Working routes
     call render_template(...), and the placeholder routes (logout, profile,
     add, edit and delete expense) return stub strings for now. Running python3 
     app.py starts a debug server at http://localhost:5001.
  2. templates/ uses template inheritance. base.html defines the shared page
     shell and has {% block %} slots (title, head, content, scripts). The other
     pages use {% extends "base.html" %} and fill in only their own content.
     Links are built with url_for('route_name'), so they refer to route function
     names in app.py rather than hard-coded URLs.
  3. static/ is loaded by base.html through url_for('static', filename=...), so
     every page gets the same CSS and JS.
  4. database/ is where the data layer will go. db.py is planned to provide
     get_db() (a SQLite connection), init_db() (creates the tables) and
     seed_db() (inserts sample data). app.py will import these once they exist.
     Right now nothing uses the database.

  Request flow (for example, visiting /login): the browser requests /login,
  Flask runs login() in app.py, which renders login.html inside base.html. The
  returned HTML then loads style.css and main.js from static/.

  Still missing: a tests/ folder (pytest is already a dependency), the database
  code, form handling for login and register, and the expense pages.
